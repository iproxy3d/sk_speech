**Сопоставление с HTML по опубликованным файлам:** обе редакции имеют одни и те же уникальные ссылочные якоря — **30/30** у «Двух типов речи» (18 страниц и 12 рисунков), **694/694** у «Формы1», **457/457** у «Шестислойной модели» (381 блок + 17 разделов + 56 рисунков + 3 таблицы). В каждом документе все пути к изображениям идут в **исходном порядке** (12/12, 0/0 и 56/56). Не обнаружены пропавшие или повторяющиеся якоря.

**Локальная навигация:** GitHub-файлы Markdown проверены по дереву ветки. В «Двух типах речи» — 48 Markdown-ссылок, из которых 26 ведут на локальные файлы и разрешаются; остальные внешние. У «Формы1» — две локальные ссылки (DOCX и review); у «Шестислойной модели» — 116 локальных ссылок, все разрешаются. Пропавших локальных файлов в трёх изданиях — **0**.

## Что сохраняется и как читается LLM

- Основной текст, заголовки, выделения и иерархические списки — в `README.md`; явные `<a id="B001"></a>` сохраняют старые точные цитатные ссылки в научных разборах. Небольшие HTML-теги `<a id>` оставлены **намеренно**: GitHub поддерживает их как якоря, а Markdown не имеет стандартного независимого якоря к каждому абзацу.
- Таблицы доступны в нативном GitHub Markdown; титульная таблица «Шестислойной модели» содержит иллюстрацию в ячейке.
- Изображения с `![alt](media/imageN.png)` берутся из того же каталога, что и HTML. PNG/JPEG не пересохранялись и не перерисовывались. Редакторские подписи с пометкой «не подпись из DOCX» оставлены отдельным курсивом.
- [Формулы, исходно нарисованные в PNG](author-documents/six-layer-model/formulas-search-4.14.md), доступны для поиска в отдельном Markdown. Исходные неточности формул и результаты экспериментальных проверок не исправлялись и не подменялись.
- [Манифест](manifest.json) содержит новый путь `markdown` и `primary_format=markdown` для каждого из трёх DOCX, сохранив адрес HTML как архивный fallback. Проверенные размеры, SHA-256 и Git SHA-1 оригиналов **не изменялись**.
- Ссылки из реестров, редакторских разборов и поисковых снимков обновлены на основной Markdown. HTML остаётся в репозитории **как резервная редакция** для сравнения, не как основное место чтения.

## Автономная перепроверка

Опубликован скрипт [`verify_markdown_migration.py`](author-documents/verify_markdown_migration.py), работающий без сети и GitHub Actions. Из полного локального checkout:

```bash
python materials/research_sources/author-documents/verify_markdown_migration.py
```

Скрипт сравнивает **сами файлы Markdown и HTML**, проверяет B/page/figure/section/table-якоря, количество ссылок и изображений, соответствие изображениям в исходных DOCX и размеры/контрольные суммы оригиналов. **В данном сеансе скрипт на полном скачанном checkout не запускался**; результаты выше получены через GitHub-объекты/дерево и структурный анализ Markdown, а не через локальный браузер.

## Ограничения и рекомендации

**Преобразование трёх документов в Markdown выполнено.** Визуальная идентичность Word/HTML/Markdown не является целью: меняется форма рендеринга (GitHub сам выбирает ширину, стили и таблицы). Для финального удаления резервных `index.html` и старого CSS следует отдельно подтвердить, что все новые Markdown-страницы корректно выглядят в GitHub и что не осталось внешних ссылок на архивные HTML. Неизменяемые DOCX и все медиа в любом случае следует оставить.

Это изменение формата **не означает**, что устранены научные или экспериментальные неопределённости из этапов 4.9–4.13.
